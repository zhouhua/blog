# 写作视角与认知框架

命题来自反复出现的论证，不是作者人设。写新稿时用来选角度和素材，不用来改句式。

## 选题逻辑

切入时机几乎都是事后或当场，很少做「行业将如何」的预报。

- 刚用过、刚看完、刚聊完：开车时想到的成本（`cost.md`），第一次做 CT（`hospital.md`），球场摔伤后看飞盘（`07-08`），一早看到语雀改价（`yuque.md`）。
- 一个说法已经在团队里当成共识：数据驱动、完课率、技术改进推不动、用户反馈要听。
- 年度复盘只用于书单，不用于「我的一年」。

角度是当事人加系统。先写自己站在哪（产品、工程师、游客、读者），再问激励、成本、定义把行为推向哪。不写旁观怒评，也不写「所有人都这么认为」。

少写的类型：没有判断的心情日记、新闻流水账、工具发布稿、纯教程步骤。时事可以进随笔（安倍、约翰逊），但几句之后就要落到一条更老的结构（子贡那句「忧在内者攻强」），不停留在事件本身。

判断树：

```
这件事我在场，或我能举出一对例子吗？
  否 → 不写，或标明「我没有采访过」
  是 → 大家默认的那个说法是什么？
        → 它在哪一层是对的（事实 / 观点 / 立场 / 指标）？
        → 翻过来之后，谁的成本更低，谁的损失更大？
        → 能落到一个下一步吗？
           否 → 收成「这并不能说明问题」
           是 → 写成判断
```

## 素材策略

一手场面优先：自己的产品（台灯、学习灯、完课率、后台）、自己的运动和出行、自己读的书。数字要能对上一个具体场景，不堆行业大盘。

权威用来借框架，不用来收尾。俞军、科斯、古德哈特、SBI、子贡，都是先说明拿它干什么，再放到自己的例子里试。采信要写出来：「不好评判是不是绝对正确，但背后的用意还是值得我们思考的。」

敏感或不确定的推断留在推断里。飞盘女孩的动机写完立刻撤掉，改成「纯属我胡说……事实上刻板印象未必正确。」不把猜测改成调查结论。

图片是素材，不是气氛。抽样看过的图：

多数稿子没有图。有图时，图要么是分类本身，要么是证据或界面，文字负责解释图里那一层。精确的界面差异、聊天原话、实验光路，只存在于图中，正文不把图复述成第二份说明书。

## 核心命题

1. 先把「事」拆开。事实独立于判断，观点来自信息和位置，立场是利益里的观点，信仰是一套你证伪不了的自洽。跟立场和信仰争对错没有结果。（`logic.md`）
2. 对错不止一种。法学家看证据，经济学家看谁避免事故的成本最低，商人看谁的损失大。个人决策用最后一种：地铁上被踩，时间比道歉值钱，就算自己的错。（`logic.md`）
3. 指标一变成目标就不再是好指标。定义一加宽，规则就变重，事情的生命力变弱。助攻争议最后收成「先定义清楚什么是传球」。（`indicators.md`、`07-19`）
4. 能用愚蠢解释的，先别用恶意解释。只处理事实，不猜动机；动机要一而再地直接互动才谈得上。（`razor.md`）
5. 数据和 AB 降低的是门槛，不是上限。容易衡量的东西会高速发展，直到被过度使用。短期迭代的成功推不出长期方向。普通需求做完，只是普通产品。（`product.md`、`data-driven.md`、`11-01`、`05-19`）
6. 用户的话要分级。反馈里的事实值得听完，未经验证的建议不直接做。一个人的正确，对大多数人仍是猜想。效用不是功能：鞋不只有保护脚。（`product.md`、`feedback.md`、`information.md`）
7. 体验差要和综合成本放在一起看。前后体验差盖不过学习、迁移、招人的成本，这个改进就不该推。过渡方案用奥卡姆剃刀，不求尽善尽美。（`tech.md`、`auto.md`）
8. 列举优点证明不了趋势。每一项优点都能找到更强的对照。热度要看谁能持续、体验能不能传播、伙伴是否都得坚持。（`07-08`）
9. 成长是可迁移的判断，不是做完的需求。换一个业务还剩什么，才算成长。观察加一段短思考就够，不必先有正确答案。（`young.md`）
10. 好对象让人重新定义自己要做的事，而不是把功能清单对齐。工具要有性格；书要经得起布局和动机的追问，宣传语不算数。（`11-01`、`2025/books.md`）
