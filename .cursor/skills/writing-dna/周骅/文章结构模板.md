# 文章结构模板

抽样覆盖思维方式、产品、成长、阅读、技术、旅行、历史和随笔。下面按体裁给可复用骨架。字数是这批稿子的常见区间，不是配额。

## 思维方式长文

`logic.md`、`causation.md`、`indicators.md`、`razor.md`、`cost.md`、`auto.md`。约 800–3000 字，`logic.md` 到 7200。

```
开篇（80–200 字）
  → 从刚遇到的一件事或一个谁都会说的词起笔
  → 用「不过」把真正要拆的对象点名
拆词
  → 小标题是概念，不是步骤
  → 每个概念：一句定义 + 一对能对质的例子 + 这个区分在沟通里怎么用
翻面
  → 把常识推论走完，再给翻的理由（成本、激励、谁的损失大）
收束
  → 一句可执行的判断，或「下次听到某某说法，留个心眼」
  → 不写「综上所述」
```

`logic.md` 的骨架是四层分类，再加一个方法（SBI），再加三种对错观。图是分类本身，正文负责把图走一遍。

## 产品 / 成长长文

`product.md`、`feedback.md`、`data-driven.md`、`young.md`、`tech.md`、`information.md`。约 1300–8000 字。

```
开篇
  → 交代观点从哪来（书、同事、自己的业务），不装成原创定律
  → 用一组已经带立场的问题当目录
每一问
  → 先把「当然不能 / 明明有用啊」说完
  → 立刻用自己业务里的一个场景翻掉它（台灯、完课率、组件规范）
  → 概念落到一个决定：听什么、不听什么、该不该做
收束
  → 原则写短，方法写成可选项
  → 数据、AB、指标是工具，方向另说
```

`product.md` 开头四问就是全文目录。小标题直接用那句要辩的话。

## 书评（年度书单）

`2024/books.md`、`2025/books.md`。单书 400–900 字，全书按书切块。

```
书名做小标题，可配书籍卡片
  → 先给阅读时的私人钩子（一首歌、一个预期）
  → 宣传语拿出来，点出它夸在哪里
  → 具体说布局、动机、闲笔哪里没接上
  → 「不过对我来说」把口味收在自己身上
  → 下一本接着写，全书最后一句见面，不升华阅读的意义
```

## 技术介绍

以 `scroll-driven-animations.md` 为准。`noise.md` 的空开场不采。

```
先给一个看得见的例子
  → 把旧办法的麻烦走一遍（要监听什么、要改什么）
  → 再抛出今天的主题，用一句话定义它解决哪一层
  → 对照：传统写法 vs 新写法，各管什么，不打「谁更强」
  → 代码块是步骤，正文是为什么这样写
```

## 现场观察（游记、时评、历史）

`xitang.md`、`hospital.md`、`talkshow.md`、`poem.md`、郑庄公上下篇。约 700–2300 字。

```
从一个自己在场的场面起笔（第一次做 CT、补完一季、驱车一个半小时）
  → 先写预期，再写预期落空的那一眼
  → 把场面收成一个结构（白天/黑夜、家事/朝局、宣传/实际）
  → 最后一句判断，可以承认矛盾仍然合理
```

历史篇从两极评价起笔，再回到当事人当时能看见的信息，不站在结局上骂人。

## 随笔

平均约 570 字。可以没有标题。`07-19` 助攻、`07-08` 飞盘、`11-01` 产品的浪漫、`05-19` AB 与模式、`06-07` 三行书摘，都算这一体。

```
从当天的场面起笔，不写导语
  话题窄时先圈死：「不好意思，今天聊足球。」
正文
  → 连列场景，直到边界走完
  → 列完说明这串列举证明不了什么，或收成更简单的定义
  → 列表里可以开玩笑，玩笑后仍要有判断
结尾
  → 一句判断，或借一句别人的话停下
  → 不另起「总结」
  → 自我更正放进括号，或单独写成「纯属我胡说」
```

极短篇允许只有场景加一句，或一句引用再补半句（`06-07`：引完「学会了沉默」，只补「还好，现有的 ai 还不会主动沉默。」）。

## 不要用的骨架

- 「为什么 + 一个还没证实的判断」当题目。先问这个判断成不成立（`logic.md`：「为什么胖的人比较懒？……等等，胖的人真的比较懒吗？」）。
- 开篇「在现代…扮演重要角色」。
- 结尾三个形容词排成愿景，或「期待有一天」式的空收（`hospital.md` 的末句偏这一类，后来的稿子更常停在判断上）。
