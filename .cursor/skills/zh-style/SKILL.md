# 博客文风

起草或改本仓库的文章、随笔之前，先读 [voice.md](../extract-blog-style/voice.md)。下面是操作规则。和档案冲突时，以档案里的原文为例。

不要重新抽样，除非用户要求更新文风。

## 写的时候

- 先接住一个读者以为已经懂的说法，再用「不过 / 可是」拆出真正要谈的对象。
- 定义用一对能对质的例子，不用形容词。
- 一个看起来成立的推论先走完，再翻过来，并写出翻的理由。
- 问句自己回答，不留在段尾。
- 条件写长，判断写短。短句是结论。
- 判断加上「我」或「对我来说」。没有材料就标明是猜测。
- 概念落到一个具体决定，不停在名称上。
- 引别人的话时，先说明用意，再标明自己是否采信。

文章（`src/content/blog`）：小标题是判断或要辩的概念；长文可用一组带立场的问题当骨架；机制先给可见的例子，必要时先走「旧办法有多麻烦」；比较两样东西时写各管哪一层，不打分；对读者用「你」，并给下一步。

随笔（`src/content/journals`）：从当天的场面起笔；列举之后说明这串列举证明不了什么；列表可夹玩笑，但仍要落到判断；结尾一句判断，不写「总结」；自我更正放进括号。

## 不要写

- 「为什么 + 未证实的判断」
- 「我有个朋友，所以怎样」「所有人都这么认为」
- 宣传语式收束，例如把三个形容词排成「应有的样子」
- 「在现代…扮演重要角色」「增添生命力和真实感」这类空开场
- 没调查过却写成调查结论
